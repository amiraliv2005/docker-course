# گزارش Dockerfile

## ۱. Dockerfile چیست و چه کاربردی دارد؟

Dockerfile یک فایل متنی است که داخلش دستورهایی می‌نویسیم تا Docker بداند چطور یک Image بسازد. مثلاً مشخص می‌کنیم از چه Image پایه‌ای استفاده کند، چه فایل‌هایی را کپی کند، چه کتابخانه‌هایی را نصب کند و در نهایت برنامه را چطور اجرا کند.

مزیت Dockerfile این است که به‌جای اینکه هر بار همه مراحل را دستی انجام بدهیم، دستورها یک‌بار نوشته می‌شوند و می‌توانیم با استفاده از آن‌ها Image را دوباره بسازیم. این کار باعث می‌شود فرایند ساخت برنامه منظم‌تر و قابل تکرار باشد.

به‌طور خلاصه، Dockerfile دستورالعمل ساخت Image است، Image شامل فایل‌ها و پیش‌نیازهای موردنیاز برنامه است و Container نمونه‌ای از Image است که اجرا می‌شود.

## ۲. چرا فایل requirements را قبل از بقیه فایل‌ها کپی می‌کنیم؟

در پروژه‌های پایتون، فایل `requirements.txt` مشخص می‌کند که برنامه به چه کتابخانه‌هایی نیاز دارد.

اگر اول همه فایل‌های برنامه را کپی کنیم و بعد کتابخانه‌ها را نصب کنیم، با هر تغییری در کد برنامه ممکن است Docker مجبور شود مراحل بعدی، از جمله نصب کتابخانه‌ها، را دوباره اجرا کند.

برای جلوگیری از این اتفاق، بهتر است ابتدا فایل وابستگی‌ها را کپی کنیم و کتابخانه‌ها را نصب کنیم؛ سپس فایل‌های اصلی برنامه را کپی کنیم.

مثال:

```dockerfile
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY app.py .
```

در این روش، اگر فقط `app.py` تغییر کند و `requirements.txt` و سایر ورودی‌های مرتبط ثابت باشند، Docker معمولاً می‌تواند از کش مرحله نصب کتابخانه‌ها استفاده کند.

این کار زمان ساخت مجدد Image را کاهش می‌دهد. البته استفاده از کش به ثابت ماندن ورودی‌های مربوط به آن مرحله و موجود بودن کش بستگی دارد.

## ۳. تفاوت ARG و ENV چیست؟

هر دو برای تعریف متغیر استفاده می‌شوند، اما کاربردشان یکسان نیست.

دستور `ARG` بیشتر برای مقادیری استفاده می‌شود که هنگام ساخت Image به آن‌ها نیاز داریم. مثلاً می‌توانیم نسخه یک نرم‌افزار را هنگام Build مشخص کنیم.

مثال:

```dockerfile
ARG APP_VERSION=1.0
```

دستور `ENV` برای تعریف متغیرهای محیطی استفاده می‌شود که در مراحل بعدی ساخت قابل استفاده‌اند و معمولاً در زمان اجرای Container هم در دسترس هستند.

مثال:

```dockerfile
ENV APP_ENV=production
```

در این مثال، برنامه می‌تواند مقدار `APP_ENV` را از محیط اجرا بخواند.

پس تفاوت اصلی این است که `ARG` برای تنظیمات زمان ساخت است، اما `ENV` برای تعریف متغیر محیطی استفاده می‌شود که معمولاً در زمان اجرای Container هم باقی می‌ماند.

نکته امنیتی: اطلاعات حساسی مثل رمز عبور و کلیدهای محرمانه را نباید بدون استفاده از روش مناسب مدیریت Secretها داخل `ARG` یا `ENV` قرار داد.

## ۴. تفاوت CMD و ENTRYPOINT چیست؟

هر دو به اجرای برنامه در Container مربوط هستند، اما نقش متفاوتی دارند.

دستور `CMD` فرمان یا آرگومان پیش‌فرض اجرای Container را مشخص می‌کند.

مثال:

```dockerfile
CMD ["python", "app.py"]
```

در این مثال، فرمان پیش‌فرض اجرای Container، اجرای فایل `app.py` با پایتون است. اگر هنگام اجرای `docker run` فرمان دیگری داده شود، در حالت معمول مقدار پیش‌فرض `CMD` جایگزین می‌شود.

دستور `ENTRYPOINT` برنامه اصلی‌ای را مشخص می‌کند که با اجرای Container راه‌اندازی می‌شود.

مثال:

```dockerfile
ENTRYPOINT ["/usr/bin/tini", "--"]
CMD ["python", "app.py"]
```

در این مثال، ابتدا `tini` اجرا می‌شود و فرمان پایتون به آن داده می‌شود. `tini` به مدیریت سیگنال‌ها و فرایندهای فرزند کمک می‌کند.

در نتیجه، `ENTRYPOINT` برنامه اصلی یا نقطه ورود Container را تعیین می‌کند و `CMD` معمولاً فرمان یا آرگومان پیش‌فرض آن را مشخص می‌کند. رفتار دقیق به نحوه تعریف این دو دستور بستگی دارد.

## ۵. چرا بهتر است Container با کاربر غیر root اجرا شود؟

کاربر `root` در لینوکس دسترسی‌های بسیار زیادی دارد. اگر برنامه‌ای که با این کاربر اجرا شده آسیب‌پذیر باشد، احتمال دارد مهاجم بتواند از دسترسی‌های بالای آن سوءاستفاده کند.

به همین دلیل، بهتر است برنامه با یک کاربر غیر root و فقط با دسترسی‌های موردنیازش اجرا شود. این کار باعث می‌شود خطرات احتمالی محدودتر شوند.

مثال:

```dockerfile
RUN useradd -m appuser
USER appuser
```

دستور `RUN useradd` کاربر `appuser` را هنگام ساخت Image ایجاد می‌کند و دستور `USER` مشخص می‌کند که دستورهای بعدی و اجرای پیش‌فرض Container با کدام کاربر انجام شوند.

نکته مهم این است که ایجاد کاربر به‌تنهایی کافی نیست؛ باید مشخص شود Container واقعاً با چه کاربری اجرا می‌شود. همچنین دسترسی فایل‌ها و پوشه‌هایی که برنامه به آن‌ها نیاز دارد باید درست تنظیم شده باشند.

## جمع‌بندی

در این بخش با مفهوم Dockerfile و کاربرد آن آشنا شدم و تفاوت `ARG` و `ENV`، همچنین `CMD` و `ENTRYPOINT` را بررسی کردم. یاد گرفتم که ترتیب دستورهای کپی فایل‌ها می‌تواند روی استفاده از Build Cache تأثیر بگذارد و اجرای برنامه با کاربر غیر root هم یکی از راه‌های کاهش ریسک امنیتی است.
